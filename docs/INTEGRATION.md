# Интеграция QazMind Web, QazMind Admin и API

Документ фиксирует текущее состояние: что сделано, что проверено и с каким результатом, что не проверено и что остаётся. Пункты «не проверено» не считаются работающими.

## 0. Админка на реальных данных и запуск в Docker

- Вход сотрудников: пароль и TOTP, приглашения, роли, отключение, завершение сессий; журнал аудита неизменяем (триггер базы). Подробно: `docs/ADMIN_ACCESS.md`, раздел 11.
- На реальных данных: обзор, ученики (блокировка, сессии, карточка), предметы и темы, уроки с версиями и рецензией, банк вопросов с редактором, модерацией и импортом CSV, журнал аудита, мониторинг, сотрудники и роли, аналитика, уведомления, поиск.
- `docker compose up -d --build` поднимает базу, API (с миграциями), Mailpit, QazMind Web и QazMind Admin; исходники подключены томами.
- Проверки: API 66 из 66 (16 новых на вход, права, рецензию, блокировку, аудит); типизация, тесты (contracts 5, web 15, admin 15) и сборки проходят; все контейнеры поднимаются, миграция 0003 применяется при старте. Страницы админки после входа (обзор, ученики, вопросы, модерация, уроки, роли, аудит, мониторинг, школы) сняты headless Chrome на отдельной тестовой базе: данные отображаются, ошибок выполнения нет.

## 1. Состав

| Часть | Где | Назначение |
|---|---|---|
| QazMind Web | `apps/web` | Лендинг, регистрация, онбординг, кабинет ученика, уроки |
| QazMind Admin | `apps/admin` | Панель платформы. Данных и записей пока нет: сервер администрирования не подключён |
| API | `apps/api` | FastAPI, PostgreSQL, миграции Alembic, CLI контента |
| Контракты | `packages/contracts` | Общий HTTP-клиент, типы ошибок и страниц, роли, пути админского API |
| Документы | `docs/` | Архитектура, интеграция, контракты, доступ к админке, примеры развёртывания |

npm workspaces, корневой `package.json` запускает оба фронтенда через `npm run dev`.

## 2. Что сделано

### packages/contracts
- `http.ts`: `createApiClient` (базовый URL, `credentials: 'include'`, CSRF double-submit, таймаут `TIMEOUT`, отмена `ABORTED`, сетевая ошибка `NETWORK_ERROR`, колбэки на 401 и 403), `ApiError`, `errorText`.
- `types.ts`: `Page<T>`, `PageQuery`, `SessionResponse`, `PLATFORM_ROLES` — семь канонических ролей, как в QazMind Admin.
- `admin.ts`: пути админского API, включая вход сотрудников и управление сотрудниками. Сервера для них пока нет.

### QazMind Web (`apps/web`)
- Демо удалено полностью: `DEMO_MODE`, прототипы школ, учителей и администрирования на данных браузера (`schoolService`), вход в админку, переключатель пространств, вход в класс по коду, привязка к школе в интерфейсе.
- Удалены демо-симулятор на пять вопросов с оценкой «из 140», демо-урок, ежедневные задачи, выдуманные ошибки и история экзаменов.
- Разделы, которые не подключены к серверу (практика, пробный экзамен, кабинеты школ, `/admin/*`), показывают заглушку «раздел в разработке» и ничего не запускают.
- Лендинг: убраны демо-продукт, симулятор, тарифы и блок для школ. Убраны выдуманные цифры: статистика «73%», длительности и результаты этапов маршрута, размеры банка заданий, обещание бесплатного доступа.
- Количества в разделе предметов взяты из спецификации ЕНТ (`docs/QAZMIND_TECHNICAL_SPEC.md`): 120 заданий и 140 баллов; обязательные предметы — 20, 10 и 10 заданий; каждый профильный — 40 заданий и 50 баллов.
- До загрузки серверного профиля используется пустой профиль, а не прототипный.
- Урок, открытый по адресу `/learn/<предмет>/<урок>`, сохраняется при перезагрузке страницы.

### QazMind Admin (`apps/admin`)
- `adminService` — честный слой данных: списки пусты, показатели `null`, каждая запись отказывает с `AdminNotConnectedError`. Интерфейс показывает статус подключения.
- Каждая страница с записью обрабатывает отказ у себя: ошибка показывается рядом с кнопкой, а успех — только после выполненного вызова (`ActionResultNotice`). Глобального перехватчика ошибок больше нет.
- Удалены мок-репозиторий, плашка «ДЕМО-РЕЖИМ», переключатель ролей, экран доступа, конфиг демо-режима.
- Выдуманные значения убраны: графики, суммы, города, школы, классы, ученики, проценты, цифры в подписях. Прочерк означает «нет данных», а не ноль.
- Импорт вопросов: CSV разбирается построчно и без значений по умолчанию. Строка с пустым полем, неизвестным предметом или неверным ключом отклоняется с номером строки. Импорт заблокирован, пока не загружен справочник предметов (`utils/questionCsv.ts`, 8 тестов).
- Редактор вопроса: прямой публикации нет, публикация идёт через рецензию. Значения по умолчанию («Казахское ханство», «Учебник МОН РК / ЕНТ 2026», теги «ЕНТ», «Подготовка») убраны.
- Редактор урока: не заполняет заглушки-блоки и цели обучения; перед сохранением проверяет название, тему и пустые блоки.
- Конструктор экзамена: проходной балл не подставляется по умолчанию, сохранение требует его задать.
- Страница «Администраторы и роли»: матрица полномочий — это спецификация. Кнопка приглашения сотрудника отключена до появления сервера и входа владельца.
- Диалоги подтверждения не обещают записи в журнал аудита, которого пока нет.

### API (`apps/api`)
- Без изменений в этом этапе. Действующие проверки: CORS по списку адресов, проверка `Origin` для изменяющих запросов (`CSRF_INVALID`), сессия в HttpOnly cookie, письма через SMTP (в локальном стеке — Mailpit).

### Инфраструктура и документация
- Примеры окружения очищены: убраны `VITE_DEMO_MODE`, `VITE_ADMIN_DEMO_MODE`, `VITE_WEB_URL`, `VITE_ADMIN_URL` (в коде не читались).
- Скрипт `export:prototype` и `scripts/` удалены: скрипт читал программу из удалённого прототипа.
- Добавлен `docs/ADMIN_ACCESS.md`: роли, владелец, жизненный цикл сотрудника, матрица полномочий, аудит, открытые решения.

## 4. Не проверено

- **Внешний вид в браузере.** Автоматизации браузера в среде нет. Удаление разделов, пустые состояния и новые заглушки не просмотрены глазами.
- **Прямые URL и обновление страницы** в браузере. Проверялись только HTTP-ответы и сборка.
- **Ручная навигация по всем разделам админки** и сценарии с отказом сервера в каждом экране.
- **Поведение веба при сбоях сети** в разделах, которые пока не подключены.

## 5. Технический долг

### QazMind Admin
1. Разделы без серверной части (школы, учителя, экзамены, задания, обращения, жалобы, лицензии, настройки, активность учеников) работают на старом `adminService` и помечены «скоро».
2. Публикация экзамена не проверяется сервером. Серверная проверка спецификации относится к этапу API.
3. Значения спецификации (120 заданий, 140 баллов, структура профиля) сейчас в коде. Должны приходить из версии спецификации на сервере.
4. Предмет `cs` (информатика) есть в админке, но не в каталоге API. Решение за владельцем продукта.
5. Профильные пары в админке и на сервере (`profile_pairs`) не сверены между собой.
6. Названия предметов в админке — клиентский справочник (`constants/subjects.ts`). Источник истины — таблица `subjects` на сервере.
7. Конструктор экзаменов не сохраняет: банка опубликованных вопросов и серверной части экзаменов ещё нет.

### QazMind Web
8. Практика и пробный экзамен (этапы 5 и 9) будут запускаться по опубликованным вопросам на сервере. Ключи ответов не должны попадать в браузер.
9. Кабинеты школ и учителей (этапы 6–8) вернутся на сервере. В вебе сейчас раздела нет.

### Общее
10. Повторный ввод кода для критичных действий и процедура восстановления владельца без второго владельца не реализованы (`docs/ADMIN_ACCESS.md`, разделы 4 и 10).
11. ИИ-черновики уроков в `apps/api/content/drafts/` не проверены экспертом. Их нельзя публиковать. Решение, оставить их или удалить, — за владельцем продукта.
