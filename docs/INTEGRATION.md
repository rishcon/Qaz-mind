## 2. Что изменено в коде

- `admin.ts`: пути админского API (`ADMIN_ENDPOINTS`). Сервера для них пока нет.

### QazMind Web (`apps/web`)
- `src/api/client.ts` использует общий транспорт. Имена экспортов сохранены, экраны не менялись.
- Смена семантики: `VITE_API_BASE_URL` теперь полный префикс (например `http://localhost:8000/api/v1`). Пустое значение означает `/api/v1` через прокси Vite.
- Маршрут `/admin/*` больше не открывает демо-страницу одобрения школ. В демо-режиме показывается `AdminEntry` со ссылкой на QazMind Admin. Вне демо-режима — заглушка «раздел закрыт», ссылки на админку нет.

- Порт 5173, `strictPort`, адрес `127.0.0.1`. Прокси `/api` на `localhost:8000`.

### QazMind Admin (`apps/admin`)

### API (`apps/api`)
- Адреса по умолчанию: `PUBLIC_APP_URL` и CORS на `5173` и `5174`.
- Для изменяющих запросов проверяется заголовок `Origin`: адрес не из списка → 403 `CSRF_INVALID`. Запросы без `Origin` (скрипты, утилиты) проверяются только токеном.
- Тест на отказ по недоверенному `Origin` и на успешный запрос с доверенным.

### Инфраструктура
- `docker-compose.yml`: контекст сборки `./apps/api`, `PUBLIC_APP_URL` и CORS на `5173`/`5174`.
- `.github/workflows/ci.yml`: фронтенд ставится из корня (`npm ci`), запускаются `typecheck`, `test`, `build`; бэкенд — из `apps/api`.
- `.env.example` в корне — справочник всех переменных. Для каждого приложения свой пример: `apps/web/.env.example`, `apps/admin/.env.example`, `apps/api/.env.example`. Секретов нет.

## 4. Технический долг

### QazMind Admin
1. **Сервис синхронный, поверх мок-репозитория.** Страницы вызывают `adminService` напрямую. Переход на API-адаптер потребует асинхронности, а значит правок во всех страницах. Это отдельная задача, она не сделана.
2. **Выдуманные значения, видимые без пометки.** Диаграмма регистраций в `OverviewPage` (`[120, 145, 138, 190, 210, 245, 230]`), `AnalyticsPage` («104 / 140», «2,140 мест», строка школы «340 учащихся»), счётчики предметов в `mockDatabase` (18 тем, 64 урока, 840 вопросов). Часть страниц помечена `DemoBadge`, часть нет. Глобальная плашка закрывает всё, но точечные значения стоит убрать.
3. **Конструктор экзаменов** (`ExamBuilder.tsx`):
   - публикация не вызывает `validateExamSpecification`, поэтому экзамен можно опубликовать с недостающими вопросами;
   - год зашит как `2026`;
   - если вопросы не выбраны, `questionCount` берётся из спецификации (120), хотя вопросов нет;
   - список предметов профиля зашит в код (`hist-kz`… теперь `history_kz`…), а не берётся из пары.
4. **Текст «120 вопросов, 140 баллов по официальной спецификации МОН РК»** в `ExamsPage` и `mockDatabase` зашит. Значения должны приходить из версии спецификации в БД.
5. **Предмет `cs`** (информатика) есть только в админке и не входит в каталог API. Решение за владельцем продукта.
6. **Профильные пары** в админке (`subject1Id`/`subject2Id`) и на сервере (`profile_pairs`) не сверены между собой. Нужна одна таблица.
7. **Редакторы вопросов и уроков** (`QuestionEditor`, `LessonEditor`, `ImportWizard`) сохраняют в мок-репозиторий без серверной проверки. Правила проверки (`validateQuestionDraft`) есть, но только на клиенте.
8. **Переключение ролей** (`RoleSwitcherModal`) меняет роль только в памяти. Это демо-механизм; на сервере роли не меняются.

### QazMind Web
9. **Экзамен считается в браузере**, ключи ответов лежат в клиентском бандле (`questions.ts`). Это этап 5 и 9.
10. **Школы, учителя и задания** работают на `localStorage` (`schoolService.ts`), доступны только в демо-режиме. Этапы 6–8.
11. **Оценка «из 140» по пяти вопросам** (`ExamPracticeSection.tsx`) остаётся на лендинге. Этап 9.
12. **`PlatformAdminPage.tsx`** не подключён. Его можно удалить после подтверждения, что функции есть в админке.

### Общее
13. **Два источника предметов** исправлены по ID, но не по данным: в админке есть свои названия, цели и количества. Общий источник — таблица `subjects` на сервере.
14. **Вход администраторов** не реализован: нет ролей на сервере, MFA, журнала административных действий. Без этого админка не может быть публичной.

- `admin/package.json` падал с ERESOLVE на `npm install`. Исправлено удалением неиспользуемых зависимостей.
- Ранее записанные результаты `lint` и `build` для админки были получены из корневого `node_modules`, а не из её собственных зависимостей. Теперь проверка идёт из workspace.
- Тесты админки (`entRules.test.ts`, 7 штук) никогда не запускались. Теперь они запускаются через `npm test`, все проходят.
- Админский `tsc` раньше не проверял код с её зависимостями. Теперь проверяется.
